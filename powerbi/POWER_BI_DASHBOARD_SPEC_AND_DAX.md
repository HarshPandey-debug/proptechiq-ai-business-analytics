# Power BI Dashboard Specification, Data Model & DAX Reference

> **Dataset Provenance Note**: All tables and metrics in this specification represent the **synthetic CampusStay Student Housing Marketplace dataset** generated by `src/generate_dataset.py` for portfolio demonstration.

## 1. Star Schema Data Model Architecture (Preventing Fan-Out in Power BI)

To ensure Power BI visuals never suffer from the 1-to-many join fan-out trap documented in `docs/AI_MISTAKE_AND_VERIFICATION_REPORT.md`, the data model is structured as a strict **Star Schema** using the cleaned CSV exports in `data/cleaned/`:

```
                  +-----------------------+
                  |     Dim_Calendar      |
                  |  Date (PK, 1-to-Many) |
                  +-----------+-----------+
                              | 1
                              | *
+--------------------+   1  * +-----------------------+ *  1   +--------------------+
|    Dim_Students    +--------+     Fact_Bookings     +--------+   Dim_Properties   |
|  student_id (PK)   |        |   booking_id (PK)     |        |  property_id (PK)  |
+--------------------+        +-----------+-----------+        +--------------------+
                                          | 1
                                          | * (Single-Direction Filter)
                              +-----------+-----------+
                              |     Fact_Payments     |
                              |   payment_id (PK)     |
                              +-----------------------+
```

### Relationship Rules in Power BI Model View

| From Table (Many `*`) | From Column | To Table (One `1`) | To Column | Cardinality | Cross-Filter Direction |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `Fact_Bookings` | `student_id` | `Dim_Students` (`students_cleaned.csv`) | `student_id` | Many-to-One (`*:1`) | **Single** (`Dim_Students` filters `Fact_Bookings`) |
| `Fact_Bookings` | `property_id` | `Dim_Properties` (`properties_cleaned.csv`) | `property_id` | Many-to-One (`*:1`) | **Single** (`Dim_Properties` filters `Fact_Bookings`) |
| `Fact_Bookings` | `booking_date` | `Dim_Calendar` (Calculated Date Table) | `Date` | Many-to-One (`*:1`) | **Single** (`Dim_Calendar` filters `Fact_Bookings`) |
| `Fact_Payments` | `booking_id` | `Fact_Bookings` (`bookings_cleaned.csv`) | `booking_id` | Many-to-One (`*:1`) | **Single** (`Fact_Bookings` filters `Fact_Payments`; never Bi-Directional) |

## 4. Step-by-Step Power BI Desktop Setup Instructions

1. **Import Cleaned Tables**:
   * Open Power BI Desktop → **Get Data** → **Text/CSV**.
   * Load `properties_cleaned.csv` (rename to `Dim_Properties`), `students_cleaned.csv` (rename to `Dim_Students`), `bookings_cleaned.csv` (rename to `Fact_Bookings`), and `payment_installments_cleaned.csv` (rename to `Fact_Payments`).
2. **Create `Dim_Calendar`**:
   * Go to **Modeling** → **New Table** and paste:
     ```dax
     Dim_Calendar = 
     ADDCOLUMNS(
         CALENDAR(DATE(2025, 11, 1), DATE(2026, 10, 31)),
         "Year", YEAR([Date]),
         "MonthNumber", MONTH([Date]),
         "YearMonth", FORMAT([Date], "YYYY-MM"),
         "MonthName", FORMAT([Date], "MMM YYYY")
     )
     ```
   * Right-click `Dim_Calendar` → **Mark as date table** → select `Date`.
3. **Configure Star Schema Relationships**:
   * In **Model View**, connect the keys as listed in Section 1 above. Verify that all relationships use **Single** cross-filter direction.
4. **Add DAX Measures**:
   * Create an empty measure table `_Measures` and paste the definitions from `powerbi/dax_measures.dax`.
